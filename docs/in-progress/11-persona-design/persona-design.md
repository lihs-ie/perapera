# ペルソナ設計書

## 1. はじめに

### 1.1 目的

本文書は、リアルタイム文字起こし翻訳 Chrome 拡張の主要利用者像を定義する。動画視聴時の単方向翻訳と、Web 会議時の双方向翻訳を中心に、利用者の目的、期待、制約、UI / UX への示唆を整理する。

## 2. ペルソナ設計方針

### 2.1 想定する利用軸

| 観点       | 軸                                        |
| ---------- | ----------------------------------------- |
| 翻訳方向   | 単方向 / 双方向                           |
| 利用場面   | 動画視聴 / Web 会議 / 複数音源監視        |
| 音声入力   | タブ音声 / マイク / 両方                  |
| 表示ニーズ | その場のオーバーレイ確認 / モニタ一覧確認 |

### 2.2 設計上の前提

1. 利用者は設定の細かさよりも、翻訳結果がすぐ画面に出ることを優先する
2. 利用者は音声ベースの翻訳支援を期待しており、長文の手入力や都度のコピーペーストを望まない
3. Web 会議利用者は、自分の発話と相手の発話が混ざらず区別されることを期待する
4. 動画視聴利用者は、映像の邪魔にならないオーバーレイ表示を期待する

## 4. ペルソナ詳細

### 4.1 PER-001 海外動画を視聴するユーザー

| 項目     | 内容                                                    |
| -------- | ------------------------------------------------------- |
| 属性     | 20 代後半から 40 代、業務学習または趣味で海外動画を視聴 |
| 利用環境 | ノート PC、Chrome、動画サイトやライブ配信サイト         |
| 主入力   | ブラウザタブ音声                                        |
| 主表示   | 動画上の翻訳オーバーレイ                                |
| 主目的   | 元音声を止めずに、内容を即座に理解したい                |

**行動特性**

- 再生中に別タブや別アプリへ視線を移したくない
- 原文よりも翻訳結果を優先して追う
- 設定変更は最小限にしたい

**主要課題**

- 字幕サイトや別翻訳ツールを併用すると視線移動が多い
- 元動画の字幕だけでは理解が追いつかない
- オーバーレイが大きすぎると映像を邪魔する

**期待体験**

- 再生中の動画に自然に翻訳が重なる
- 数秒待たずに発話単位で翻訳が見える
- 必要なら原文も補助的に確認できる

**重要要件**

- 翻訳オーバーレイの非侵襲性
- 低遅延表示
- タブ音声の簡単な開始操作

### 4.2 PER-002 国際 Web 会議に参加するユーザー

| 項目     | 内容                                                     |
| -------- | -------------------------------------------------------- |
| 属性     | 20 代後半から 50 代、業務で海外メンバーや顧客と会議する  |
| 利用環境 | ノート PC、Chrome、Web 会議ツール、外付けマイク利用あり  |
| 主入力   | タブ音声 + マイク音声                                    |
| 主表示   | 会議タブ上のオーバーレイ、または拡張専用モニタ           |
| 主目的   | 相手の発話を理解し、自分の発話も翻訳補助として確認したい |

**行動特性**

- 会議を止めずに理解補助を得たい
- 相手音声と自分音声を区別したい
- トラブル時はすぐ再接続や表示切替をしたい

**主要課題**

- 会議中に別サービスへ音声を渡す操作が煩雑
- 双方向翻訳では、どちらの発話か分からなくなると使えない
- 遅延が大きいと会話のターンに追いつけない

**期待体験**

- 相手の発話は自分の言語で即時に読める
- 自分の発話も相手向け言語で確認できる
- 双方向でも行ごとに話者やソースが区別される

**重要要件**

- マイクとタブ音声の同時処理
- 双方向翻訳でのソース識別
- エラー時の即時回復導線

### 4.3 PER-003 複数音源を監視するオペレータ

| 項目     | 内容                                              |
| -------- | ------------------------------------------------- |
| 属性     | 配信監視、サポート、通訳補助、QA 担当             |
| 利用環境 | デスクトップ PC、複数タブ、場合により外部音声入力 |
| 主入力   | 複数タブ音声、補助マイク入力                      |
| 主表示   | Side Panel、拡張専用モニタタブ                    |
| 主目的   | 複数音源の状態と翻訳結果をまとめて監視したい      |

**行動特性**

- 映像よりも状態一覧を優先して見る
- 翻訳品質より、見逃しなく監視できることを重視する
- 異常ソースをすぐ切り分けたい

**主要課題**

- 音源が増えると、どの字幕がどのソースか混乱しやすい
- 翻訳停止や権限エラーを個別に追いづらい
- 複数ツール併用では管理負荷が高い

**期待体験**

- ソース単位で状態、原文、翻訳を分けて見られる
- 劣化中のソースが一目で分かる
- 必要時に対象ソースだけ詳細を開ける

**重要要件**

- 最大 3 ソース同時処理時の視認性
- ソースごとの状態表示
- オーバーレイとモニタの使い分け

## 5. 共通ジョブ理論

### 5.1 Jobs To Be Done

| JTBD                                 | 成功条件                             |
| ------------------------------------ | ------------------------------------ |
| 視聴中の動画内容を理解したい         | 視線移動なく翻訳を追える             |
| 会議中の相手発話を聞き漏らしたくない | 発話から短時間で翻訳が見える         |
| 自分の発話がどう伝わるか確認したい   | 双方向の表示が混ざらず確認できる     |
| 複数音源の状況を一画面で把握したい   | ソースごとの差異と異常が明確に分かる |

### 5.2 不採用ペルソナ

以下は MVP の主対象外とする。

- 完全自動の高精度同時通訳音声を期待する専門通訳利用
- Chrome 外のネイティブアプリ上へ直接オーバーレイを出したい利用
- オフラインのみで高精度翻訳を完結させたい利用

## 6. 設計への示唆

### 6.1 要件への示唆

1. 単方向翻訳と双方向翻訳の両方を正式な利用文脈として扱う
2. 双方向利用では `sourceId` と表示ラベルを必須にする
3. 速度最優先の非機能要件は全ペルソナ共通で重要度が高い

### 6.2 UI/UX への示唆

1. 動画視聴用途ではオーバーレイを既定表示面とする
2. Web 会議用途ではオーバーレイとモニタ表示を切り替え可能にする
3. 会議用途では自分音声と相手音声を色、ラベル、位置のいずれかで区別する
4. 複数音源用途では Side Panel に状態と最新翻訳を集約する

### 6.3 テストへの示唆

1. 単方向視聴シナリオと双方向会議シナリオを分けて評価する
2. 双方向翻訳では話者混同が起きないことを確認する
3. 翻訳遅延は動画視聴よりも Web 会議シナリオで厳しめに評価する
