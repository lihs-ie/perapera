# セキュリティ設計書

## 1. はじめに

### 1.1 目的

本文書は、リアルタイム文字起こし翻訳 Chrome 拡張におけるセキュリティ設計を定義する。Chrome 拡張、Relay API、外部 STT / 翻訳 / 将来の TTS プロバイダを含む構成に対して、脅威分析、認証・認可、データ保護、ログ方針を明確化することを目的とする。

### 1.2 準拠基準・ガイドライン

| 基準                                      | 概要                                                       |
| ----------------------------------------- | ---------------------------------------------------------- |
| OWASP Top 10 (2021)                       | Web アプリケーションおよび API の主要脅威への対策基準      |
| Chrome Extensions Security Best Practices | MV3 拡張の権限最小化、CSP、メッセージ境界保護の設計指針    |
| Chrome Web Store Program Policies         | 権限利用、データ取得、利用者同意に関する配布基準           |
| 個人情報保護法                            | 音声由来字幕・翻訳テキストを含む個人関連情報の取り扱い基準 |

## 2. 脅威分析

### 2.1 脅威モデル（STRIDE）

| カテゴリ                           | 脅威                                                           | 対象                                       | 対策                                                                                   |
| ---------------------------------- | -------------------------------------------------------------- | ------------------------------------------ | -------------------------------------------------------------------------------------- |
| Spoofing（なりすまし）             | 不正クライアントが拡張を装って Relay API に接続する            | Relay API、WebSocket                       | 短命 `streamToken`、Bearer 認証、トークン失効時刻検証、TLS 必須                        |
| Tampering（改ざん）                | WebSocket イベントや拡張内メッセージが改ざんされる             | Relay API、Service Worker、Content Script  | JSON スキーマ検証、`sessionId` / `sequence` 整合性確認、拡張内部メッセージの送信元確認 |
| Repudiation（否認）                | 利用者や運用者が開始・停止・エクスポート・設定変更を否認する   | 拡張 UI、Relay API、運用ログ               | 構造化監査ログ、`sessionId` / `requestId` 記録、時刻同期、操作イベントの永続化         |
| Information Disclosure（情報漏洩） | 音声由来字幕、翻訳テキスト、トークン、API キーが漏洩する       | ブラウザ保存領域、ログ、外部通信、運用基盤 | 生音声の非永続化、API キーのサーバー管理、ログマスキング、TLS、保存期間最小化          |
| Denial of Service（サービス拒否）  | 過剰なフレーム送信や大量接続で Relay API や外部 API が枯渇する | Relay API、プロバイダ接続                  | レートリミット、同時セッション上限、タイムアウト、バックプレッシャー、劣化運転         |
| Elevation of Privilege（権限昇格） | 不要な Chrome 権限や管理権限を悪用される                       | Chrome 拡張、運用基盤                      | MV3 最小権限、運用者 RBAC、Secrets 参照権限分離、不要 API 非採用                       |

### 2.2 リスク評価

| 脅威                                  | 影響度 | 発生確率 | リスクレベル | 対応優先度 |
| ------------------------------------- | ------ | -------- | ------------ | ---------- |
| API キーやトークンの漏洩              | 高     | 中       | 高           | 最優先     |
| 字幕・翻訳テキストの漏洩              | 高     | 中       | 高           | 最優先     |
| Relay API への DoS / 過剰接続         | 中     | 中       | 中           | 高         |
| Content Script 経由の UI 改ざんや注入 | 中     | 中       | 中           | 高         |
| エクスポート結果の誤共有              | 中     | 中       | 中           | 中         |
| 運用者権限の過剰付与                  | 高     | 低       | 中           | 高         |

## 3. 認証設計

### 3.1 認証方式

MVP ではエンドユーザーのアプリ内ログインは必須としない。認証対象は主に `Chrome 拡張 ↔ Relay API`、および `Relay API ↔ 外部プロバイダ` とする。

| 項目                       | 仕様                                                               |
| -------------------------- | ------------------------------------------------------------------ |
| 認証方式                   | Bearer Token                                                       |
| HTTP 制御 API              | `Authorization: Bearer <access_token>`                             |
| WebSocket                  | `Authorization: Bearer <stream_token>`                             |
| アクセストークン有効期限   | 実装時に確定。少なくとも長期固定値を避け、ローテーション可能とする |
| ストリームトークン有効期限 | 短命。`POST /sessions` で発行し、セッション開始用途に限定する      |
| 外部プロバイダ認証         | Relay API からのサーバーサイド資格情報のみ使用                     |

### 3.2 パスワードポリシー

MVP ではアプリ独自のユーザーアカウントとパスワード認証を導入しないため、本項目は適用外とする。

| 項目                 | 要件   |
| -------------------- | ------ |
| 最小文字数           | 適用外 |
| 文字種要件           | 適用外 |
| ハッシュアルゴリズム | 適用外 |
| 連続失敗時のロック   | 適用外 |

### 3.3 多要素認証

利用者向け MFA は MVP 対象外とする。将来、管理コンソールやクラウド同期機能を追加する場合は、管理者アカウントに MFA を必須化する。

| 項目 | 仕様                     |
| ---- | ------------------------ |
| 方式 | MVP では適用外           |
| 対象 | 将来の管理者向け運用画面 |

## 4. 認可設計

### 4.1 権限モデル

| 項目   | 仕様                              |
| ------ | --------------------------------- |
| モデル | Chrome 権限モデル + 運用基盤 RBAC |

### 4.2 ロール定義

MVP ではアプリ利用者ロールを分けず、Chrome 拡張利用者はローカル操作主体として扱う。サーバー側は運用者権限を分離する。

| ロール         | 説明       | 主な権限                                                 |
| -------------- | ---------- | -------------------------------------------------------- |
| extension-user | 拡張利用者 | 自身の端末上でのソース開始、停止、設定変更、エクスポート |
| operator       | 運用担当   | 監査ログ参照、稼働状況確認、レート制限調整               |
| admin          | 管理者     | Secrets 管理、運用設定変更、障害時の保守操作             |

### 4.3 リソースアクセス制御

| リソース                   | admin | operator | extension-user                        | 未認証 |
| -------------------------- | ----- | -------- | ------------------------------------- | ------ |
| Relay API `/health`        | 参照  | 参照     | -                                     | 参照   |
| Relay API `/sessions`      | 管理  | 参照     | 自身のセッション作成                  | -      |
| Relay WebSocket `/relay`   | 管理  | 参照     | 自身の `streamToken` に紐づく接続のみ | -      |
| 監査ログ                   | 参照  | 参照     | -                                     | -      |
| Secrets / API キー         | 管理  | -        | -                                     | -      |
| ローカル字幕・翻訳保持領域 | -     | -        | 自端末分のみ                          | -      |

## 5. データ保護

### 5.1 暗号化方針

| 対象                | 方式                           | アルゴリズム                       |
| ------------------- | ------------------------------ | ---------------------------------- |
| 通信の暗号化        | TLS                            | TLS 1.3 を優先、最低 TLS 1.2       |
| WebSocket 通信      | WSS                            | TLS 終端を含む暗号化               |
| 保存データの暗号化  | 基盤提供の暗号化 + OS 保護領域 | 実行基盤の標準暗号化を利用         |
| トークン / API キー | シークレット管理               | クラウドのシークレットストアで管理 |

### 5.2 機密データの取り扱い

| 分類     | 例                                                        | 取り扱い方針                                                               |
| -------- | --------------------------------------------------------- | -------------------------------------------------------------------------- |
| 極秘     | STT / 翻訳 / TTS API キー、署名鍵、長期アクセストークン   | 拡張内へ保持しない。Relay API 側のシークレットストアで管理し、ログ出力禁止 |
| 機密     | `streamToken`、字幕テキスト、翻訳結果、運用ログ内の識別子 | 保存期間を最小化し、ログはマスキングして出力する                           |
| 社内限定 | レイテンシメトリクス、エラー統計、バージョン情報          | 監査対象として保持し、運用者 RBAC で参照制御する                           |

### 5.3 データ最小化方針

- 初期設定では生音声を永続保存しない
- ローカル保存対象は字幕・翻訳結果・最小限のメタデータに限定する
- 部分字幕は必要最小限の短期保持とし、長期保存対象は確定字幕を優先する
- エクスポートは利用者の明示操作時のみ実行する
- ログには原文全文、翻訳全文、音声フレーム本体を出力しない

## 6. セキュリティ対策

### 6.1 入力値検証

- 拡張 UI と Relay API の双方で入力値を検証する
- Relay API は `sourceType`、言語コード、`overlayTarget`、`frameDurationMs` などを JSON スキーマで再検証する
- WebSocket イベントは `eventType` ごとの必須項目、型、範囲、`sessionId` 整合性を検証する
- 音声フレームは上限サイズを超える場合に即時拒否する

### 6.2 CSRF 対策

本システムは Cookie ベース認証を前提としないため、一般的な CSRF リスクは低い。HTTP / WebSocket ともに Bearer Token 前提とし、ブラウザ任せの資格情報送信を避ける。

| 項目 | 対策                                                |
| ---- | --------------------------------------------------- |
| 方式 | Cookie 非依存の Bearer 認証、CORS 制限、Origin 検証 |

### 6.3 XSS 対策

- オーバーレイ UI は React によるエスケープを前提とし、`dangerouslySetInnerHTML` を禁止する
- Content Script UI は Shadow DOM で隔離し、ページ側 CSS / DOM の影響を最小化する
- 字幕・翻訳テキストは HTML として解釈せず、常にプレーンテキストとして描画する
- MV3 の CSP を維持し、任意スクリプト実行やリモートコード読み込みを禁止する

### 6.4 SQL インジェクション対策

MVP のホットパスでは RDBMS を前提としないため、SQL インジェクションの主リスクは低い。将来サーバー側で永続 DB を導入する場合は、パラメータ化クエリまたは ORM を必須とする。

- 文字列連結でのクエリ生成を禁止する
- 監査ログ検索用の管理機能を追加する場合も同方針を適用する

### 6.5 その他の対策

| 対策               | 方式                                                                                  |
| ------------------ | ------------------------------------------------------------------------------------- |
| Chrome 権限最小化  | `tabCapture`、`offscreen`、`sidePanel` 等の必要最小限に限定し、未使用権限を追加しない |
| CORS               | Relay API は許可オリジンを拡張起点と必要な運用系に限定する                            |
| レートリミット     | `POST /sessions`、WebSocket 同時接続、`audio.frame` を API 仕様どおり制限する         |
| トークン再利用防止 | `streamToken` を短命化し、セッション開始用途へ限定する                                |
| ログマスキング     | `Authorization` ヘッダー、API キー、字幕本文を平文出力しない                          |
| 依存脆弱性対策     | `pnpm audit` 相当のチェック、Dependabot 相当の更新監視を CI に組み込む                |
| 障害時の劣化運転   | 翻訳障害時は `degraded` へ移行し、文字起こし単体を継続する                            |

## 7. 監査ログ

### 7.1 記録項目

| イベント         | 記録項目                                                                  |
| ---------------- | ------------------------------------------------------------------------- |
| セッション開始   | `sessionId`、`sourceType`、開始時刻、拡張バージョン、成否                 |
| セッション停止   | `sessionId`、停止理由、停止時刻                                           |
| 権限拒否         | 音声ソース種別、拒否時刻、画面種別                                        |
| Relay API エラー | `requestId`、`sessionId`、エラーコード、HTTP ステータスまたは `eventType` |
| 再接続           | `sessionId`、試行回数、原因、成否                                         |
| エクスポート     | `sessionId`、形式、実行時刻、成否                                         |
| 運用者操作       | 実行者ロール、対象設定、変更前後、時刻                                    |

### 7.2 保存方針

| 項目         | 仕様                                                               |
| ------------ | ------------------------------------------------------------------ |
| 保存先       | Relay API 側の集中ログ基盤、拡張側は最小限のローカルデバッグログ   |
| 保存期間     | 監査ログは 90 日以上を初期方針とし、業務要件に応じて延長可能とする |
| アクセス制御 | `operator` 以上のみ参照可能、Secrets 関連は `admin` のみ           |
| 改ざん防止   | 集中ログ基盤側の追記専用運用とアクセス制御で担保する               |

## 8. セキュリティ運用上の前提

- 外部プロバイダの API キーは Relay API 側にのみ配置する
- Chrome Web Store 配布時は、取得データと用途を申請内容およびプライバシーポリシーと一致させる
- 利用者が取得対象音声を処理する正当な権限を持つことを前提とする
- 将来クラウド同期を導入する場合は、本設計を再評価し、保存データ分類と越境移転要件を更新する
